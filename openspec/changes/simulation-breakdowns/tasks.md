- [x] 1.1 Подпуть `@impuls/platforms/segments` → `simulator-segments.ts`. Модуль импортирует только `@impuls/core`; экспортировать `impressionMultiplier`, `priceMultiplier` и доли `DEFAULT_DEVICES`. Проверка — `pnpm -r type-check`; в импортах подпути нет адаптера Директа.
- [x] 1.2 Чистая `campaignTraffic(state, campaignId)` рядом с `campaignRoom`: минус-фразы и корректировки кампании на сейчас по `settingsLog` и `settings`, как у `settingsOf`, и минус-фразы запуска. Проверка — юнит-тест на состояния до и после `logSettings` и на старое состояние без журнала.
- [x] 1.3 `recordPeriod` принимает у объявления необязательные строки за период `segments: { device: Row[]; query: Row[] }`. Он раскладывает их по дням пропорционально остатку строки, наибольшим остатком (design, решение 3), и пишет в ячейку `entered`. Проверка — юнит-тесты симулятора:
  - сумма строк за день равна ячейке дня по каждой метрике и измерению;
  - сумма строки за дни равна её итогу за период;
  - период через понедельник и с урезанными лимитами дня.
- [x] 1.4 `getBreakdown` суммирует строки внесённых ячеек за даты запроса; ячейка без строк, как раньше, разреза не даёт. Сжатие ячеек суммирует строки, если сливает внесённые. Проверка — юнит-тесты: разрез за период и за 14 дней, захватывающие два периода, равен сумме строк; старое состояние без строк даёт пустой разрез.

## 2. Раскладка и форма окна (apps/worker/src/simulation-period.ts)

- [x] 2.1 `PeriodMarket`, `junkQueryOf(keywords)` (самый короткий основной запрос и первое подходящее слово, иначе `null`) и веса сегментов по отметкам, минус-фразам и корректировкам (design, решение 4). Проверка — юнит-тесты:
  - «маникюр» → «маникюр фото», в том числе при обычных минус-словах мастера при запуске;
  - основной запрос со словом «фото» → «маникюр идеи»; минус-фразы запуска «фото» и «идеи» → «маникюр отзывы»;
  - минус-фраза «фото» обнуляет вес ненужного запроса;
  - −25% на телефонах меняет их долю и цену перехода, как `segmentCells`.
- [x] 2.2 `splitPeriod`: строки объявления за период по устройствам и запросам (только поиск) наибольшим остатком. В строке обращения ≤ переходов ≤ показов, расход только при переходах. Равные остатки идут в порядке, сдвинутом на число из первой даты и id объявления. Проверка — юнит-тесты на цифрах сценариев спецификации:
  - 4 200 ₽ с ненужным запросом → 1 050 ₽ ± 1 ₽ и 0 обращений;
  - 9 000 ₽ и 11 обращений с отметкой телефонов → 5 400/3, 3 150/7, 450/1;
  - без отметок 2 × (4 200 ₽, 7 обращений) → телефоны и компьютеры в пределах цели 1 000 ₽;
  - суммы каждого измерения равны итогам; тот же ввод даёт тот же результат.
- [x] 2.3 `PeriodFormDirection` получает `keywords`, `negativeKeywords`, `deviceAdjustments` и `junkQuery`; `PeriodForm` — `market` прошлого завершённого шага, по умолчанию отметки сняты. `periodForm` читает настройки через `campaignTraffic`. Проверка — юнит-тесты `periodForm`: поиск и сайты-партнёры, отметки из последнего завершённого шага, а не из упавшего.
- [x] 2.4 `suggestPeriod` с множителями `q` и `p` прошлого и нынешнего периода (design, решение 5). Отметки и настройки прошлого периода берутся из его шага, у старых шагов они ровные. Проверка — юнит-тесты:
  - после минус-фразы на ненужный запрос подставленная цена обращения ниже прежней при любом шуме;
  - без изменений отметок и настроек цена обращения близка к прежней (сценарий «Цифры продолжают прошлый период»);
  - подставленные цифры проходят `checkPeriod`.
- [x] 2.5 Строка-пояснение под направлением по введённым цифрам: «Около 1 050 ₽ из 4 200 ₽ — на запрос «…», без обращений», «С телефонов обращение выйдет примерно вчетверо дороже, чем с компьютера», «Реклама уже не показывается по запросу «…»». При нулевом расходе строки нет. Проверка — юнит-тесты текстов; в текстах нет слов из стоп-листа `change-history`.

## 3. Воркер симуляции и агент

- [x] 3.1 Действие `period` принимает необязательное `market`. `livePeriod` под блокировкой строит форму, считает `splitPeriod` по настройкам на момент выполнения и передаёт строки в `recordPeriod`. Шаг сохраняет `market` и настройки направлений в начале периода (`SimulationStep`). Проверка — юнит-тесты `simulation-mode`:
  - разрез после периода с отметкой непустой;
  - без `market` разбивка ровная;
  - «Продолжить расчёт» не пишет строки второй раз;
  - «Начать заново» снимает отметки.
- [x] 3.2 `PERIOD_REVIEW_INSTRUCTIONS` шаг 4 по design (решение 7), версия блока `2026-11-06.1`; снапшот-тест версии инструкций обновлён. Тестовая политика в `period_review` вызывает `analystLevers` и применяет минус-фразу и корректировку по внесённой разбивке. Проверка — юнит-тест политики на ответе `get_breakdown` с ненужным запросом и с дорогими телефонами.
