## Context

Что уже есть (см. proposal.md — Why):
- `AgentRuntime` в `packages/agent` с реализациями: `OpenAiAgentRuntime` (Agents API, сессия на ход, наши function tools через `toolHandlers`) и тестовые политики (`IdlePolicy`, `RandomPolicy`, `AdversarialPolicy`, `ReplayPolicy`).
- Ход агента — `runAgentTurn` в `apps/worker/src/agent-turn.ts`:
  - снимок `TurnSnapshot` из allowlist-полей;
  - инструменты действий с обоснованием `{ reasonCode, text }`; текст проверяется `validateExplanation` по числам снимка и стоп-листу;
  - лимиты 20 действий в сутки и 30 вызовов за ход;
  - журнал хода с итоговым сообщением `summary`, которое нигде не показывается.
- Глобальный флаг `agent_enabled` выключен миграцией 0008. Без агента решают правила `safetyNet`. Если флаг включён, правила ждут агента 24 часа, а запуск проверки — 7 дней (`EXPERIMENT_DELAY_DAYS`), даже если хода не было.
- В симуляции контекст получает `IdlePolicy`, флаг агента выключается при запуске (`launchSimulation`).
- Исследование Agents API (`docs/research/agents-api.md`):
  - ход длится около 17 секунд;
  - лимита затрат на сессию нет;
  - расход токенов не приходит в `turn.completed`.
- Месячный лимит затрат на модель есть в спецификации `ad-agent`, но не реализован.

## Goals / Non-Goals

**Goals:**
- Одна сущность «инсайт» для решений агента и правил, с фактами, которые невозможно исказить.
- Агент по умолчанию, но безопасная деградация: правила действуют сразу, когда хода не было.
- Предсказуемая стоимость: учёт по ходам, лимиты на бизнес и на прогон симуляции.
- Симуляция с агентом не тормозит другие симуляции и честно показывает, что время стоит, пока агент думает.

**Non-Goals:**
- Память агента сверх недавних инсайтов.
- Новые действия агента (ключевые фразы, зона показа).
- Сравнение агента с правилами в интерфейсе.
- Разбивка статистики по часам и регионам.

## Decisions

### 1. Факты — перечень в снимке, агент ссылается на них по ключу

Снимок хода получает `facts`: список `{ key, object, metric, period, value }`. Ключ стабилен и читаем, например `ad:<id>:spend:14d`, `direction:<id>:cost_per_lead:7d`, `budget:left:month`. Инсайт агента содержит до 4 ключей. Сервис отклоняет неизвестные ключи и подставляет значения сам.

Числа в свободных текстах по-прежнему проверяет `validateExplanation` по тем же фактам.

- **Почему не сверять числа, которые агент пишет в фактах:** модель охотно округляет («≈517 ₽»), и такие факты отклонялись бы часто. По ключу ошибиться в значении невозможно, а модели проще выбрать факт, чем переписать число.
- **Альтернатива — свободные факты текстом.** Отвергнута: «на основе каких данных» должно быть проверяемым.

Перечень фактов собирается из allowlist-полей снимка (`ad-agent` «Минимизация данных»): расход, показы, переходы, обращения и цена обращения за 14 дней, за последние 7 и за предыдущие 7 дней; цена обращения по площадкам; бюджет, расход месяца, ровный темп и остаток; цель; цифры идущей проверки. Чистая функция `snapshotFactCatalog(view)` живёт в worker рядом с `buildSnapshot`, а проверка ключей и текстов — в `packages/core` рядом с `validateExplanation`.

### 2. Инструменты: инсайт вместо обоснования, наблюдение и чтение

- **Инструменты действий.** Поле `justification { reasonCode, text }` заменяется на `insight { reasonCode, observation, factKeys[2..4], next }`.
  - «Что решили» строит сервис из ответа исполнителя: применено, урезано с причиной, отклонено с причиной.
  - Объяснение в истории — `observation` и действие.
- **`report_insight`** — наблюдение без действия: `{ observation, factKeys, decision, next }`, где `decision` — «пока ничего не меняем, потому что…». Проверки те же. В лимит действий не входит, но входит в лимит вызовов за ход.
- **`get_recent_insights`** — инсайты за 14 дней: текст, ключи фактов и их значения на тот момент, решение. Без ID других бизнесов.

Новая версия инструкций агента:
- каждое действие — с инсайтом;
- заметное наблюдение без действия — через `report_insight`;
- не повторять недавние выводы, если цифры не изменились;
- итоговое сообщение — «разбор дня» в одном абзаце.

Тестовые политики обновляются, чтобы выдавать инсайты (eval и BDD).

### 3. Хранение: таблица `insights` и ссылка из истории

Поля `insights`:
- `id`, `business_id`, `turn_id` (null для правил), `source` (`agent` | `rule`), `created_at` (время бизнеса, в симуляции виртуальное);
- `observation`, `facts` (jsonb с объектом, показателем, периодом и значением на момент инсайта);
- `decision` (jsonb: вид, текст, статус ответа ограничителя);
- `next`, `change_ids` (jsonb).

В `change_log` добавляется `insight_id` (null). Разбор дня — это `turns.summary` после проверки и признак `summary_valid`; инсайты группируются в ленте по `turn_id`, инсайты правил — по дню.

Хранятся как история изменений (персональных данных в них нет) и удаляются в `deleteLaunchData`, то есть при «Начать заново» и «Запустить по-настоящему». Альтернатива — хранить инсайт внутри записи истории — отвергнута: наблюдение без действия истории не создаёт.

### 4. Инсайты правил — из шаблонов

`renderTemplate` уже строит объяснение по фактам правила. Добавляется `renderInsight(reasonCode, facts)`:
- «Что заметили» и «Что дальше» — шаблоны для `SAFETY_*`, `EXPERIMENT_*`, `BUDGET_PAUSE_SHORTAGE`, `BUDGET_EXHAUSTED`, `BUDGET_NEW_MONTH*`;
- факты — из тех же чисел, по которым правило сработало (код, а не модель, поэтому они достоверны без перечня);
- `BUDGET_FIT` инсайтов не создаёт (`isBudgetAdjustment`).

Инсайт создаётся в том же месте, где правило вызывает исполнитель, после ответа исполнителя.

### 5. Страховка ждёт только после состоявшегося хода

Вход `safetyNet` меняется: вместо `agentEnabled` передаётся `agentActed` — был ли за последние 24 часа завершённый ход агента, который принимает решения. У `AgentRuntime` появляется признак `decides`: `false` у `IdlePolicy`, `true` у модели и остальных тестовых политик.

Так:
- в CI на `IdlePolicy` правила работают сразу, как сейчас, и калибровка сценариев симуляции не сдвигается;
- в бою, когда Agents API недоступен или исчерпан лимит, страховка не ждёт сутки.

`EXPERIMENT_DELAY_DAYS` тоже применяется только при `agentActed`. Альтернатива — считать «ход состоялся» по флагу — отвергнута: именно она сейчас задерживает решения при недоступном агенте.

### 6. Агент по умолчанию: флаг, конфигурация, выключатель

- Миграция переключает глобальный `agent_enabled` на `true`; выключатели по бизнесу и глобальный остаются.
- В `DIRECT_API_MODE=production` конфигурация worker требует `AGENT_RUNTIME=openai`, `OPENAI_AGENT_MODEL` и лимиты затрат и не стартует без них (No-Fallbacks).
- Стенд разработчика — так же. CI и e2e — `AGENT_RUNTIME=idle`.
- Принцип «агент выключен по умолчанию» меняется в `openspec/config.yaml` (контекст проекта) и `AGENTS.md`.

### 7. Затраты: учёт по ходу и два лимита

- Первая задача — короткое исследование: отдаёт ли API ходов (`turns`) расход токенов завершённого хода. Итог проверки 30.10.2026: не отдаёт ни в событии, ни в `turns`, ни в сессии — рабочий путь «оценка» (`docs/research/agents-api.md`).
- Если отдаёт, `OpenAiAgentRuntime` читает его после `turn.completed`.
- Если нет, runtime считает оценку: токены переданного (инструкции, снимок, ответы инструментов) и полученного (тексты, аргументы вызовов) по счётчику символов с коэффициентом запаса. Это записывается в журнал хода как оценка.
- Цена за токен — из конфигурации для модели.
- Лимиты в конфигурации: `AGENT_MONTHLY_LIMIT_RUB` на бизнес и `AGENT_SIMULATION_RUN_LIMIT_RUB` на прогон. Ход не начинается, если лимит исчерпан. Начатый ход доводится до конца: расход становится известен только в конце хода, а цену одного хода ограничивают 30 вызовов инструментов и таймаут хода, так что лимит может быть превышен не больше чем на один ход.
- Команда видит затраты командой CLI `agent costs --month`.

Альтернатива — лимит на сессию через `spend_control` — недоступна: API отвечает 400.

### 8. Симуляция с агентом

- `simulationWorld` получает агента из базового контекста (`base.agent`) вместо `IdlePolicy`; `launchSimulation` больше не выключает флаг. Креативы вариантов A/B остаются шаблонными (решение 2 `add-simulation-mode`), чтобы не умножать платные вызовы.
- **Время стоит, пока агент думает.**
  - `advanceWorld` после часа с ходом агента прерывает цикл, а тикер сдвигает `lastTickAt` на реальное время хода (агент в мире симуляции замеряется по реальным часам): реальное время хода не превращается в виртуальное, а несделанные часы переходят в следующий тик.
  - Статус пульта получает `agentTurn: { day } | null` по журналу ходов (ход в статусе `running`), и пульт показывает «Агент разбирает 8-й день…».
- **Тикер не блокирует другие симуляции.**
  - Сейчас `tickSimulations` проходит симуляции по очереди, и ход в 17 секунд задержал бы все остальные.
  - Тикер запускает тик каждой симуляции отдельно и не начинает новый, пока предыдущий тик этой симуляции не закончился.
  - Одновременно воркер ведёт до 3 симуляций: тик держит до трёх замков-соединений (симуляция, ход агента, бизнес), поэтому замки живут на отдельном пуле соединений, рассчитанном на эти тики и обработчики pg-boss, и не отнимают соединения у запросов.
- **Действия пульта во время хода** ждут замок симуляции; кнопки показывают ожидание. Пауза применяется сразу после хода.
  - «+1 день» идёт частями, каждая заканчивается после хода агента; между частями симуляция в статусе `stepping` (тикер её не двигает), и любое другое действие пульта — пауза, «Продолжить», «Начать заново» — завершает шаг. Иначе пауза ждала бы конца виртуального дня со всеми его ходами (на стенде с `gpt-6-luna` — около двух минут).
  - Web-задания worker выполняет параллельно (до 5): шаг симуляции с ходами агента не должен задерживать задания других владельцев, например «Вернуть как было». Порядок заданий одного бизнеса держат замки бизнеса и симуляции; пул замков рассчитан на тики, задания и почасовой обход.
- **Скорость.** Месяц с агентом — это 5 минут симуляции и 30 разборов примерно по 17 секунд, всего около 13–14 минут. Требование «30 дней за 6 минут» остаётся для прогона без вызовов модели (`simulation-mode`).

### 9. Экраны

- **Сводка** (`SummaryView`) — три плитки без кольца, «Нужно ваше участие», лента. «Где показываем рекламу» — за ссылкой «Цифры по площадкам». «Что сервис сделал за неделю» и `ExperimentCard` уходят: проверка становится первым инсайтом ленты с прогрессом и текстами вариантов (`DiffText`).
- **Экран симуляции** (`DecisionsView`) — сравнение с графиком, итог, чек-лист и лента. Строка «На самом деле…» строится по правде объявления или рекламы, о которой инсайт. Ленты, график бюджета и карточка A/B удаляются вместе с их моделью.
- **История** — ссылка «Почему» на инсайт (якорь в ленте).
- **Компоненты.** Лента — общий компонент `InsightFeed` для сводки и экрана симуляции. Карточка инсайта: четыре части, автор, время, «Вернуть как было» через существующий `RollbackDialog`.

## Risks / Trade-offs

- **[Риск] Агент решает хуже правил.**
  → Ограничители и бюджет он не обходит. Перед выпуском — eval (`pnpm eval:agent`) с проверкой инсайтов, а сравнение «с сервисом / без» в симуляции покажет эффект. Выключатель возвращает правила за минуту.
- **[Риск] Стоимость: агент у всех бизнесов и 30 ходов на прогон симуляции.**
  → Учёт по ходу, лимиты на бизнес и на прогон; при исчерпании решают правила, и пользователь видит это в разборе дня.
- **[Риск] Нет точного расхода токенов в API.**
  → Оценка с запасом (решение 7) и проектный лимит в кабинете OpenAI как внешний предохранитель.
- **[Риск] Инъекция через тексты сайта в карточке.**
  → Тексты инсайтов проходят стоп-лист и проверку чисел, факты берутся из снимка, действия — через ограничители. Карточка в снимке остаётся данными, а не инструкциями.
- **[Компромисс] Симуляция с агентом медленнее и не воспроизводится.** Это честно показано пульту и в подтверждении «Начать заново». Точные повторы остаются в CI на тестовых политиках.
- **[Риск] Ход держит замок симуляции до 10 минут при зависании Agents API.**
  → Таймаут хода уже есть. Для симуляции он короче (конфигурация), а после таймаута действует страховка.

## Migration Plan

1. Миграция:
   - таблица `insights`;
   - колонка `change_log.insight_id`;
   - колонки затрат и `summary_valid` в журнале ходов;
   - глобальный `agent_enabled = true`.

   Без удаления данных.
2. Выкатка worker с новой конфигурацией (OpenAI, лимиты затрат), затем web. Старые записи истории без инсайта показываются как раньше, без ссылки «Почему».
3. Перед включением в бою — eval на новой версии инструкций (платно, по запросу).
4. Откат — глобальный выключатель агента (`cli flags set agent_enabled off`): решения сразу переходят к правилам, их инсайты продолжают создаваться. Полный откат — прежние образы; таблица инсайтов не мешает старому коду.

## Open Questions

- Цены токенов и запас оценки задаются конфигурацией при выкатке. Модель агента — `gpt-6-luna` (решение 30.10.2026 по `pnpm eval:agent`: правило выпуска пройдено при цене хода ≈0,4 ₽ против ≈8,7 ₽ у `gpt-6.1-sol`; ход дольше — ≈50–60 с против ≈31 с; `docs/research/agents-api.md`).
- Отдаёт ли API ходов расход токенов — первая задача; от ответа зависит только источник цифры, а не подход.
