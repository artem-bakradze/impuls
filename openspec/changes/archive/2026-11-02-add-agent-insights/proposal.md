## Why

Сейчас рекламой управляют детерминированные правила, а агент на OpenAI Agents API выключен по умолчанию. Пользователь видит итог на сводке и графиках, а «почему» — в отдельных записях истории. Связать данные, вывод и решение он должен сам. Заказчик решил 30.10.2026:
- решения принимает агент, правила остаются страховкой;
- пользователь видит инсайты вместо графиков: что заметили, на каких данных, что решили, что дальше.

## What Changes

- **Агент включён по умолчанию** у всех бизнесов, в обоих режимах. В режиме «Яндекс Директ» он принимает решения о рекламе. В режиме «Симуляция» решает тоже он, на том же Agents API (платные вызовы, около 30 ходов за прогон в 30 дней). **BREAKING** для принципа проекта «агент — необязательное дополнение, по умолчанию выключен»: принцип меняется в конфигурации OpenSpec и в `AGENTS.md`.
- **Правила — страховка.** Отключение неэффективного, масштабирование, A/B-проверки и `budget-guard` остаются детерминированными. Если агент промолчал 24 часа, они действуют сами. Если ход агента не состоялся (Agents API недоступен, исчерпан лимит затрат, агент выключен выключателем), правила действуют сразу, без ожидания. Ограничители и бюджет агент обойти не может, как и сейчас.
- **Инсайт — новая сущность.** Карточка из четырёх частей:
  - «Что заметили» — простыми словами;
  - «На каких данных» — 2–4 факта с объектом, показателем и периодом;
  - «Что решили» — действие и ответ ограничителя: применено, урезано, отклонено с причиной. Или «пока ничего не меняем, потому что…»;
  - «Что дальше» — что и когда проверим.

  Каждое число в фактах сервис сверяет со снимком данных хода: факт с числом не из снимка отклоняется.
- **Инструменты агента.**
  - Каждое действие передаётся вместе со своим инсайтом вместо прежнего обоснования «код причины + текст».
  - Новый инструмент — наблюдение без действия.
  - Новый инструмент чтения — недавние инсайты, чтобы не повторяться.
  - Снимок хода расширяется агрегированной статистикой: показы, переходы, 7 дней против предыдущих 7, цена обращения по площадкам, темп расхода бюджета, идущая проверка.
- **Решения правил** показываются тем же форматом инсайтов: они строятся из шаблонов и фактов, по которым правило сработало. Подстройки лимитов защитой бюджета в инсайты не попадают и остаются в истории.
- **Разбор дня.** Итоговое сообщение агента владельцу сейчас хранится в журнале хода и не показывается. Оно становится заголовком дня в ленте инсайтов.
- **Сводка — без графиков.**
  - Сверху три главные цифры: потрачено из бюджета, обращения, цена обращения против цели.
  - Ниже «Нужно ваше участие», «Разбор дня» и лента инсайтов.
  - Кольцо прогресса и «Где показываем рекламу» убираются с первого экрана; цифры по площадкам — по ссылке «Подробнее».
  - «Сейчас проверяем» становится инсайтом с прогрессом.
- **Экран «Как сервис принимает решения» в симуляции.** Остаются сравнение «с сервисом / без сервиса» (единственный график, доказательство эффекта) и чек-лист. Ленты по объявлениям, график бюджета и карточка A/B заменяются лентой инсайтов. У инсайта об объявлении или рекламе есть строка «На самом деле…» из скрытой правды сценария.
- **История.** Каждая запись, созданная решением, ссылается на свой инсайт. Журнал хода для специалистов остаётся.
- **Симуляция с агентом.**
  - Пока агент разбирает день, виртуальное время стоит, а пульт показывает «Агент разбирает 8-й день…».
  - Требование «30 дней за 6 минут» относится к прогону без вызова модели.
  - «Начать заново» повторяет рынок, но не обязан повторять решения агента. Точная воспроизводимость остаётся у прогонов с тестовыми политиками агента в CI.
- **Стоимость.** Расход токенов считается по каждому ходу. Месячный лимит затрат на бизнес есть в `ad-agent`, но не реализован, теперь его нужно сделать. Отдельно вводится лимит на прогон симуляции. При исчерпании лимита ходов нет, решают правила, а пользователь видит это в ленте.

Вне объёма:
- аналитика по часам и регионам;
- новые действия агента (ключевые фразы, зона показа);
- память агента сверх ленты инсайтов;
- сравнение «с агентом / без агента» в интерфейсе.

## Capabilities

### New Capabilities
- `insights`: инсайт как карточка «что заметили / на каких данных / что решили / что дальше», проверка фактов по снимку, инсайты агента и инсайты правил из шаблонов, разбор дня, лента инсайтов, связь с историей.

### Modified Capabilities
- `ad-agent`: агент включён по умолчанию и работает в симуляции («Ходы агента»); инсайты в инструментах и новые инструменты («Доступ только через инструменты сервиса»); обоснование действия становится инсайтом («Обоснование каждого действия»); расширенный перечень полей снимка («Минимизация данных»); учёт затрат, лимит на бизнес и на прогон симуляции («Лимиты агента»); правила как страховка без ожидания, если ход не состоялся («Работа без агента»).
- `optimization-engine`: страховочные правила ждут агента 24 часа только после состоявшегося хода, иначе действуют сразу («Страховочное отключение неэффективной рекламы», «Страховочное масштабирование эффективной рекламы»).
- `analytics`: сводка — три цифры, «Нужно ваше участие», разбор дня и лента инсайтов вместо графиков и блоков действий («Сводка»).
- `change-history`: запись, созданная решением, ссылается на свой инсайт («Запись каждого изменения»).
- `simulation-mode`: в симуляции решает агент («Режим бизнеса «Симуляция»»); воспроизводимость рынка вместо воспроизводимости решений («Сценарии рынка»); время стоит, пока агент думает, а требование скорости — для прогона без модели («Виртуальное время и пульт»); экран решений — сравнение, чек-лист и инсайты с правдой сценария вместо лент и графиков («Экран «Как сервис принимает решения»»).

## Impact

- **БД.** Таблица инсайтов (бизнес, ход, источник «агент / правило», время, тексты, факты, решение, ссылки на записи истории). Ссылка на инсайт в `change_log`. Учёт затрат по ходам. Глобальный флаг `agent_enabled` переключается на «включён». Нужна сгенерированная миграция.
- **`packages/agent`.**
  - Схемы инструментов: инсайт вместо обоснования, `report_insight`, `get_recent_insights`.
  - Расширенный `TurnSnapshot`.
  - Новая версия инструкций, подсчёт токенов в `OpenAIAgentRuntime`.
  - Тестовые политики выдают инсайты.
- **`packages/core`.** Проверка фактов инсайта по снимку (детерминированно, рядом с `validateExplanation`). Страховочные правила получают признак «ход агента состоялся» вместо «агент включён».
- **`apps/worker`.**
  - `agent-turn.ts`: расширенный снимок, инсайты, затраты и лимиты.
  - Инсайты правил из шаблонов.
  - Симуляция вызывает агента своего бизнеса, а тикер ждёт хода.
  - Изоляция затрат симуляции.
- **`apps/web`.**
  - Сводка, лента инсайтов, разбор дня.
  - Экран решений симуляции.
  - Ссылки из истории на инсайт.
  - Пульт со статусом «агент разбирает день».
- **Эксплуатация.**
  - `AGENT_RUNTIME=openai` и ключ OpenAI обязательны в боевом окружении и на стенде; без них сервис не стартует (No-Fallbacks).
  - CI и e2e работают на тестовых политиках бесплатно.
  - Перед выпуском — eval агента (`pnpm eval:agent`, платный, по запросу).
- **Документация и правила.** Принцип «агент выключен по умолчанию» в `openspec/config.yaml` и `AGENTS.md`, `docs/architecture.md`, `docs/deployment.md` (стоимость, лимиты, выключатель).
- **Порядок архивации:** `bootstrap-ad-autopilot-mvp` → `replace-direct-sandbox` → `simplify-mvp-scope` → `add-simulation-mode` → это изменение.
