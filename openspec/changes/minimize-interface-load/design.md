## Context

После `simplify-service-work-screen` в `apps/web` есть четыре экрана бизнеса: `/summary` (`SummaryView`, модель `summary-model`), `/history` (`HistoryView`, `buildHistory`), `/simulation` (`ServiceWorkView`, `buildServiceWork`, только симуляция) и `/settings` (`SettingsView`). Мастер — шесть шагов (`WIZARD_STEPS`, номер шага хранится в `businesses.onboarding_step`). Публичный пример — `/demo` (`PublicDemoView`, `product-demo`). Журнал помощника уже строится из сохранённых ходов, инсайтов, гипотез и истории (`buildServiceWork`), но только для симуляции и только из решений сервиса.

Предыдущие изменения `improve-product-clarity-and-trust`, `reduce-interface-overload`, `weekly-simulation-triggered-agent`, `simplify-service-work-screen` ещё не архивированы; их требования к этим экранам заменяются здесь.

## Goals / Non-Goals

**Goals:**
- Один экран результатов для обоих режимов на основе существующих моделей, без новых данных в БД.
- Мастер из трёх шагов без потери проверок, которые сейчас делают шаги 3–5.
- Меньше кода в `apps/web`: удаляются `HistoryView` как экран, `DecisionsView`-подобные остатки, `PublicDemoView`, графики сводки.

**Non-Goals:**
- Изменения команд, исполнителя, ограничителей, правил отката, агента и его инструкций.
- Новый дизайн-язык: используются текущие стили главного экрана симуляции.
- Уведомления, письма и вход — без изменений.

## Decisions

**1. Главный экран живёт по адресу `/summary`, навигация называет его «Реклама».** `/history` и `/simulation` делают серверный `redirect` на `/summary`, сохраняя якорь записи (`/history#<id>` → `/summary#log-<id>`, `?week=N` → `/summary?week=N`). Альтернатива — новый адрес `/ads`: чище, но ломает ссылки из писем и `homePath`; выигрыша для владельца нет.

**2. Одна модель экрана для обоих режимов.** Загрузчик главного экрана собирает: три числа месяца (из `summary-model`, без переключателя периода), объявления и журнал (`buildServiceWork`), задачи владельца и предупреждения учёта (из текущей сводки). Для симуляции добавляются `comparison` и `truthOf`; для Директа `truthOf` не передаётся, и строки «На самом деле» не появляются. `ServiceWorkView` становится `AdsHomeView`; `WeekBriefCard` заменяется плитками трёх чисел и строкой «За неделю: N изменений · проверяю M гипотез» над журналом.

**3. Журнал — это история.** `buildServiceWork` дополняется записями истории, у которых нет инсайта сервиса: правки владельца, кабинет Директа, запуск, записи защиты бюджета кроме подстроек лимитов (`isBudgetAdjustment`). Они идут в журнал своими днями строкой «Вы: …» / «В кабинете Директа: …» из `describeDiff`. Строка изменения получает `RollbackDialog` из истории (последствия, цепочки, расхождения — без изменений) и одно раскрытие с фактами инсайта и ссылкой на журнал хода. Альтернатива — оставить `/history` отдельным экраном «для полной истории»: это та же информация второй раз.

**4. Подстройки защиты бюджета — в «Для специалистов».** Подпись бюджета на главном: «Сервис сам держит расход в бюджете месяца». Перечень подстроек (`isBudgetAdjustment`) с «было → стало» по дням — в существующем свёрнутом блоке настроек; кнопки отката у них и так нет.

**5. Действия на карточке объявления.** «Изменить текст» (`UpdateAdText`) и «Отключить» / «Включить» (`PauseAd` / `ResumeAd`) переносятся из раздела «Объявления» настроек вместе с его формами и ограничениями (последнее объявление рекламы, модерация). Отправка — через существующие web-маршруты, которые ставят команды в очередь. Клик по карточке по-прежнему фильтрует журнал; действия — отдельные кнопки поверх, как метка изменения.

**6. Мастер из трёх шагов, переход по сохранённому номеру.** `WIZARD_STEPS` = «Где вас найти?», «Вот как мы вас поняли», «Объявления и запуск». Старый номер шага переводится при чтении: 1→1, 2–4→2, 5–6→3; при сохранении пишется новый. Миграции БД не нужно: столбец остаётся целым числом. `reopenWizard(businessId, 6)` в `simulation-mode.ts` меняется на шаг 3 — единственная правка worker. Выбор обращений берёт текущие значения по умолчанию (`GOAL_OPTIONS`), проверка счётчика запускается после шага 1 в фоне, как сейчас на шаге 3, и показывается в итоге шага 3. `GoalsStep` становится строкой итога с раскрытием выбора; после запуска выбор хранится только в черновике мастера, команды его изменения нет, поэтому в настройках он показывается без редактирования; `BudgetStep` — полем под `CardStep`; `PreviewStep` и `LaunchStep` — один шаг.

**7. Демо удаляется.** `/demo` → `redirect("/")`; удаляются `PublicDemoView`, `product-demo` и кнопка «Посмотреть на примере» в `LoginCard`. Главная оставляет условия демосервиса и одно действие входа «Попробовать на своём бизнесе».

**8. Оговорки об учебном рынке.** Удаляются подписи «Учебные данные», «Изменения проверяются в учебном рынке», «Изменение применится в учебном рынке», текст «Реклама запущена в учебном рынке…» в журнале. Остаются пульт, подпись сравнения и пояснение учёта обращений в настройках симуляции.

## Risks / Trade-offs

- [Длинный журнал в настоящем режиме за месяцы работы] → журнал грузит последние 8 недель и кнопку «Раньше» сверху; поиск по истории не нужен владельцу малого бизнеса.
- [Без недельного переключателя владелец не увидит «как прошла неделя»] → строка над журналом и разделители недель в журнале; сравнение плиток — с тем же числом дней прошлого месяца.
- [Выбор обращений по умолчанию может не подходить бизнесу без формы на сайте] → строка итога «Что считаем обращением» видна до запуска, предупреждение учёта на «Рекламе» остаётся.
- [Убирая демо, теряем просмотр без входа] → вход через Google — один шаг, а симуляция показывает решения на своём бизнесе, что убедительнее вымышленного.
- [Большой объём правок интерфейса за раз] → задачи разбиты так, что каждая группа оставляет рабочий сервис: сначала главный экран и редиректы, затем мастер, затем настройки и демо.

## Migration Plan

Выкладка одной версией web и worker (правка номера шага). Сохранённые черновики мастера переводятся при чтении. Ссылки на `/history`, `/simulation`, `/demo` продолжают работать через редиректы. Откат — предыдущая версия web; данные не меняются.
