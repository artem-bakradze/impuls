## Why

Симуляция — главный способ показать, как сервис принимает решения, но сейчас это плеер с часами: время тикает, цифры меняются, а сам процесс не виден. Агент при этом вызывает модель каждое утро, хотя смотрит окна за 7 и 14 дней, и при небольшом бюджете большинство разборов заканчиваются «пока ничего не меняю». Это платные вызовы и шум в ленте. В симуляции это видно сильнее всего: 30 платных ходов за прогон, из них решений — единицы.

## What Changes

- **Агент по поводу.** Каждое утро остаётся детерминированная оценка, но модель вызывается, только когда есть повод:
  - объект стал или перестал быть неэффективным;
  - объект вышел из «Собираем данные»;
  - у эффективной рекламы есть запас для прибавки;
  - пограничное объявление вот-вот получит страховочную проверку;
  - резкая разница с прошлой неделей;
  - наступил день проверки гипотезы;
  - правка пользователя или в кабинете, отказ модерации, итог эксперимента, запуск.

  Поводы считает код. Находка, которую уже видел последний состоявшийся ход, повторно повода не даёт. Разбор недели по понедельникам остаётся всегда.
- **День без повода — не сбой.** В ленте одна строка «Посмотрели рекламу — менять ничего не нужно», подряд идущие такие дни объединяются. Страховочные правила в такой день работают так, как при включённом агенте: действуют по находкам, у которых агент уже был 24 часа. Режим «решают только правила» (сразу, без ожидания) остаётся для выключенного, недоступного или вышедшего за лимит агента.
- **Симуляция по неделям. BREAKING для пульта:** основное действие пульта — «Прожить неделю».
  - Выбор скорости, непрерывный ход времени и «До следующего решения» убираются, «+1 день» уходит в меню.
  - Время движется только по шагам: без фонового хода и без искусственных задержек.
- **История недели.** После шага экран «Как сервис принимает решения» проигрывает три сцены:
  - «Неделя прошла»: дни, счётчики, таблица объявлений с цифрами, оценкой кода и правдой сценария;
  - «Сервис разбирает неделю»: инсайты по очереди, факты подсвечивают строки таблицы;
  - «Решение»: что сделали, было → стало, ответ ограничителя, «Вернуть как было», сдвиг линии с сервисом и без.

  Есть «Показать сразу» и вариант без анимации. Историю прошлых недель можно посмотреть снова. Сцены строятся только из сохранённых данных и журналов ходов.
- **Повтор прогона.** «Начать заново» предлагает два варианта:
  - «Повторить этот прогон» — те же решения из журналов ходов, без вызовов модели, те же цифры;
  - «Прогнать заново» — агент решает заново.

  Если во время повтора пользователь действует иначе, чем в исходном прогоне, дальше решает агент на модели, и пульт об этом говорит.
- Сводка в симуляции предлагает «Прожить первую неделю» вместо «Перемотать до первого решения». Пометка на экранах становится короче: «Симуляция — реклама не показывается».

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ad-agent`: ходы по поводам вместо ежедневного вызова модели; новое требование «Поводы для хода агента»; уточнение «Работы без агента»: день без повода — не работа без агента.
- `optimization-engine`: страховочное отключение и масштабирование учитывают день без повода как день с доступным агентом.
- `insights`: «Разбор дня» без хода агента в день без повода и объединение таких дней.
- `simulation-mode`: пульт по неделям вместо скорости и непрерывного времени; история недели из трёх сцен; повтор прогона; экран «Как сервис принимает решения» начинается с истории недели; короче пометка режима.
- `analytics`: сводка в симуляции предлагает «Прожить первую неделю».

## Impact

- **Worker:**
  - `jobs.ts` (`dailyEvaluation`: поводы, исход дня, страховочные правила);
  - новый чистый расчёт поводов в `packages/core`;
  - `agent-turn.ts` (триггер с поводами);
  - `simulation-mode.ts` (шаг недели, убрать бегущий таймер и скорость, повтор прогона через `ReplayPolicy` с сохранённым итоговым сообщением);
  - хранилище: находки последнего хода и признак повтора у записи симуляции. Нужна миграция Drizzle.
- **Agent:** `ReplayPolicy` возвращает записанное итоговое сообщение хода.
- **Web:**
  - `SimulationBar` (новый пульт);
  - экран «Как сервис принимает решения» (история недели, новая модель недели в `simulation-screen.ts`);
  - `InsightFeed` (объединённые тихие дни);
  - `SummaryView`;
  - тексты шага 6 мастера про «месяц за 5 минут»;
  - API `/api/simulation` (новые действия, без скорости).
- **Тесты:** BDD для поводов, тихих дней и страховочных правил; сценарии симуляции по неделям и повтора; Vitest для расчёта поводов и модели недели; e2e симуляции.
- **Стоимость:** меньше вызовов модели на бизнес и на прогон симуляции; повтор прогона бесплатен.
