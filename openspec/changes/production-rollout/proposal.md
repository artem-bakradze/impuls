## Why

`bootstrap-ad-autopilot-mvp` описывает и реализует MVP, но 22 его задачи нельзя закрыть из репозитория: заявка на доступ к API Директа, OAuth-приложения, хостинг, staging, контрактные тесты на боевом аккаунте, юзабилити-тест с живыми владельцами и пилот требуют внешних систем, людей и согласований. Пока они лежат в `bootstrap`, изменение нельзя заархивировать, и по нему нельзя понять, что осталось сделать продукту, а что — коду. Разделяем: `bootstrap` — реализация MVP, это изменение — вывод сервиса в production и приёмка у заказчика.

## What Changes

- Новое изменение отвечает за всё, что нельзя выполнить без внешнего мира: доступ к API, OAuth-приложения, юридическая проверка, хостинг, staging и production, проверка на боевом аккаунте, юзабилити-тест, пилот и письменное согласование отклонений от ТЗ.
- Задачи `bootstrap-ad-autopilot-mvp` 0.1, 0.2, 0.3, 0.5, 0.6, 0.7, 1.10, 3.3, 3.4, 10.4, 12.5, 13.1, 13.2, 13.3, 13.4 переносятся сюда; в `bootstrap` они отмечаются выполненными с пометкой о переносе. Контрактная часть задачи 7.5 переносится сюда, остальная закрывается в `bootstrap`.
- Поведение сервиса не меняется: ни требований, ни кода это изменение не добавляет, поэтому спецификации у него нет (`skip_specs`).
- Первым идёт согласование отклонений от ТЗ: без письменного подтверждения по второй площадке, изображениям и видео приёмка критериев ТЗ невозможна, а пилот теряет смысл.

## Impact

- `openspec/changes/bootstrap-ad-autopilot-mvp/tasks.md`: отметки о переносе задач.
- `docs/ops.md`: заявка на доступ к API, выбор хостинга, staging и production.
- `docs/research/`: юридическое заключение по OpenAI API, заметки интервью, отчёт юзабилити-теста, отчёт пилота.
- Внешние системы: Яндекс Директ API и OAuth, хостинг-провайдер, OpenAI API через прокси, электронная почта для писем сервиса.
- Код не меняется. Найденные на боевом API расхождения оформляются отдельными изменениями, как уже сделано в `replace-direct-sandbox`.
