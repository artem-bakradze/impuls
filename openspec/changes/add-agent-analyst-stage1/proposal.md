## Why

Агент на Agents API сейчас «умный, но слепой и со связанными руками». Он видит только дневные итоги по объявлениям и умеет три вещи: отключить, добавить денег, запустить проверку варианта. Поэтому eval не отличает его от страховочных правил: на таких данных лучше и не решить.

Заказчик решил 30.10.2026 сделать из агента сильного таргетолога-аналитика и начать с этапа 1. Это сознательно выходит за рамки ТЗ MVP.

## What Changes

- **Разрезы данных по запросу агента.**
  - Новый инструмент чтения отдаёт по рекламе за 14 дней разрез по поисковым запросам и по устройствам: телефоны, компьютеры, планшеты. Агент сам решает, куда копнуть, — общий снимок хода не растёт.
  - Цифры разрезов становятся фактами хода и проверяются в инсайтах так же, как остальные.
  - Хватает ли данных для вывода по запросу или устройству, решает детерминированный код, а не модель.
- **Новые рычаги** — через исполнитель команд, ограничители, историю и «Вернуть как было»:
  - минус-фразы для рекламы — по поисковым запросам, которые тратят деньги без обращений;
  - корректировки ставок для телефонов и компьютеров.

  Ограничители не дают отминусовать собственные ключевые фразы рекламы, выйти за допустимый диапазон корректировок и менять их чаще недели. Страховочные правила новые рычаги не используют: без агента реклама работает как раньше.
- **Еженедельный стратегический разбор.**
  - По понедельникам сильная модель (`gpt-6.1-sol`) смотрит разрезы, итоги проверок и журнал гипотез и составляет план на неделю.
  - Ежедневные ходы остаются на `gpt-6-luna`.
  - Затраты обоих входят в те же лимиты.
  - Владелец видит «Разбор недели» в ленте инсайтов.
- **Журнал гипотез** — память агента между ходами: что проверяем, на каких фактах, к какому дню, что выяснили. Агент читает и обновляет его инструментами. Владелец видит в «Разборе недели», что сервис проверяет и что выяснил.
- **Поисковые запросы** — тексты пользователей Яндекса. Агенту уходят только запросы, повторявшиеся достаточно часто. Запросы с номерами телефонов, адресами почты и длинными числами отбрасываются до передачи в модель.
- **Симулятор знает правду** по устройствам и поисковым запросам: мусорные запросы, дорогие обращения с телефонов. Он применяет минус-фразы и корректировки ставок.
- **Новые сценарии eval,** где выигрывает только аналитик. Правило выпуска строже: на этих сценариях агент обязан быть дешевле страховочных правил не меньше чем на 10%.

## Capabilities

### New Capabilities

Нет: этап 1 расширяет существующие возможности.

### Modified Capabilities

- `ad-agent`:
  - инструменты разрезов, минус-фраз и корректировок по устройствам;
  - еженедельный стратегический разбор на отдельной модели;
  - журнал гипотез;
  - фильтр поисковых запросов перед передачей в модель.
- `optimization-engine`: ограничители минус-фраз и корректировок ставок по устройствам.
- `platform-integration`: разрезы статистики по запросам и устройствам; минус-фразы и корректировки ставок в Директе; сверка этих настроек с кабинетом.
- `insights`: факты из разрезов; «Разбор недели» с гипотезами в ленте.
- `change-history`: минус-фразы и корректировки в истории с откатом.
- `testing-harness`: правда симулятора по устройствам и запросам; сценарии аналитика в eval и строгое правило выпуска.

## Impact

- **`packages/platforms`:**
  - в контракте площадки: разрезы статистики, минус-фразы и корректировки в патче кампании, их текущее состояние у кампании;
  - адаптер Директа: Reports, Campaigns, BidModifiers;
  - симулятор: правда по сегментам и её применение.
- **`packages/core`:**
  - новые команды — добавить и убрать минус-фразы, корректировка по устройству;
  - ограничители этих команд;
  - вердикт «данных достаточно» по сегменту;
  - фильтр поисковых запросов.
- **`packages/agent`:**
  - инструменты разрезов, минус-фраз, корректировок и гипотез;
  - новая версия инструкций с «плейбуком» аналитика;
  - отдельные инструкции для разбора недели;
  - эвристическая тестовая политика использует новые рычаги.
- **`apps/worker`:**
  - разрезы в ходе агента, факты из них;
  - триггер «разбор недели» и отдельный runtime сильной модели с его ценами;
  - хранилище гипотез;
  - сверка новых настроек;
  - сценарии eval.
- **`packages/db`:** минус-фразы и корректировки направления; таблица гипотез. Миграция без удалений.
- **`apps/web`:**
  - тексты действий и «было → стало» для новых команд в истории и инсайтах;
  - «Разбор недели» с гипотезами в ленте.
- **Конфигурация:** `OPENAI_STRATEGY_MODEL` и цены её токенов — необязательные. Без них разбор недели идёт на модели ежедневных ходов.
- **Затраты:** ориентир ≈60–100 ₽ в месяц на бизнес по оценке сервиса (4 разбора недели на Sol, ежедневные ходы на Luna с разрезами). Лимит `AGENT_MONTHLY_LIMIT_RUB` нужно поднять.
- **Директ:** до реализации get-запросами на тестовом аккаунте проверить поля Reports (`Query`, `Device`, обращения по цели), диапазоны `BidModifiers` и поведение `NegativeKeywords`. Записывающие контрактные тесты — только по запросу, на черновиках.
- **Порядок архивации:** … → `add-simulation-mode` → `add-agent-insights` → это изменение. Пользовательские сценарии симуляции не меняются: решение об одном сценарии — отдельным изменением.
