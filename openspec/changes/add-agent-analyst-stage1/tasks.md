## 6. Eval и поведение

- [x] 6.1 Сценарии eval «мусорные запросы», «дорогие телефоны», «оба сразу»; вердикт выпуска различает сценарии аналитика (≤ 0,9 × правил) и остальные (≤ правил), доли проверок ≥ 0,9; обе модели в прогоне; проверка — unit-тест вердикта и `pnpm eval:agent --dry-run`, где эвристическая политика выигрывает на сценариях аналитика
- [x] 6.2 BDD по сценариям спецификаций:
  - `ad-agent`: мусорный запрос виден агенту, запрос с телефоном не уходит в модель, мало данных по устройству, агент минусует мусорный запрос, обращения с телефонов дороже, понедельник, лимит исчерпан, гипотеза открыта и закрыта, слишком много гипотез;
  - `optimization-engine`: все сценарии ограничителей;
  - `platform-integration`: минус-фраза дошла, корректировка изменена в кабинете, разрез совпадает с итогом;
  - `insights`: инсайт о мусорном запросе, сегмент не запрашивали, разбор недели;
  - `change-history`: откат одной минус-фразы и корректировки;
  - `testing-harness`: минус-фраза в симуляторе, разрез согласован.

  Проверка — `pnpm test:bdd` зелёный.
- [x] 6.3 E2E на тестовой политике: в истории есть «Добавили минус-фразу» с «Почему» и откатом, в ленте — «Разбор недели»; проверка — `pnpm --filter @impuls/web exec playwright test` зелёный
