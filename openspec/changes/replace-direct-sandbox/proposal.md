## Why

Яндекс отключил песочницу API Директа 15.07.2026 (история изменений API: «Песочница больше недоступна»). Спецификация, конфигурация и контрактные тесты `bootstrap-ad-autopilot-mvp` опираются на песочницу, поэтому совместимость адаптера с настоящим Директом сейчас проверить нечем, а режим `sandbox` указывает на несуществующий адрес. Одновременно в контракте площадки нет данных, без которых кампания в настоящем Директе не создаётся или ничего не показывает: группы объявлений с регионами, ключевые фразы, ссылка на посадочную страницу, канал «Сайты-партнёры», цель Метрики и целевая стоимость для стратегии с оплатой за обращения.

## What Changes

- **BREAKING** Режим `DIRECT_API_MODE=sandbox` удаляется. Остаются `simulator` (локальная разработка, CI, staging) и `production` (пилот и боевая работа). Конфигурация с `sandbox` отклоняется при старте с явной ошибкой.
- Плашка «Тестовый режим — реклама не показывается» показывается в режиме `simulator`.
- **BREAKING** Контрактные тесты переводятся с песочницы на боевой API Директа и работают только в выделенном тестовом аккаунте и только с черновиками: кампании с префиксом `impuls-contract-`, без отправки на модерацию, с удалением за собой; объекты без префикса тесты не изменяют. Переменные `DIRECT_SANDBOX_TOKEN` и `DIRECT_SANDBOX_CLIENT_LOGIN` заменяются на `DIRECT_CONTRACT_TOKEN` и `DIRECT_CONTRACT_LOGIN`; без них, при неодобренной заявке на доступ к API или при чужом аккаунте тесты падают сразу.
- Подключение Директа владельцем бизнеса идёт через отдельное OAuth-приложение Яндекса для авторизации пользователей с адресом возврата `<APP_URL>/api/direct/oauth/callback`. Приложение для отладки используется только для ручного получения токена контрактных тестов.
- Контракт площадки дополняется данными для запуска в настоящем Директе: канал направления (поиск или сайты-партнёры), регионы показа, ключевые и минус-фразы для поиска, ссылка на посадочную страницу с UTM-метками, цель Метрики и целевая стоимость обращения для стратегии с оплатой за обращения. Обходные хуки адаптера для групп, ссылки и параметров стратегии убираются.
- **BREAKING** Собственный сайт пользователя обязателен для запуска: на него ведут все объявления. ТЗ исходит из того, что сайт есть («код аналитики пользователь размещает на своём сайте»). Мини-сайт для бизнесов без сайта переносится за пределы MVP: его требования удаляются из спецификации, код остаётся как задел, форма в настройках скрывается.
- Worker подключает адаптер Директа в режиме `production` вместо ошибки «адаптер не реализован».
- Документация (AGENTS.md, `docs/`, `openspec/config.yaml`) и задачи `bootstrap-ad-autopilot-mvp`, ссылающиеся на песочницу, приводятся в соответствие.

### Modified Capabilities
- `platform-integration`: режимы окружения без песочницы; подключение аккаунта через пользовательское OAuth-приложение с проверкой `state`; структура создаваемых кампаний дополняется группой с регионами, ключевыми и минус-фразами, ссылкой на посадочную страницу, каналом и параметрами стратегии с оплатой за обращения.
- `testing-harness`: контрактные тесты с боевым API в выделенном тестовом аккаунте вместо песочницы, правила безопасности тестов.
- `business-onboarding`: шаг «Где вас найти?» требует ссылку на собственный сайт.
- `campaign-settings`: раздел «Сайт» показывает адрес собственного сайта, без мини-сайта.
- `mini-site`: требования удаляются из MVP.

## Impact

- **Код**: `packages/platforms` (контракт `AdPlatform`, адаптер `yandex-direct`, симулятор, контрактные тесты), `apps/worker` (конфигурация, `main.ts`, запуск рекламы), `apps/web` (конфигурация, шаг подключения Директа, маршрут OAuth callback, плашка тестового режима).
- **Конфигурация**: удаляется значение `sandbox`; новые переменные `DIRECT_CONTRACT_TOKEN`, `DIRECT_CONTRACT_LOGIN`; `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET` относятся к пользовательскому OAuth-приложению.
- **Внешние зависимости**: одобренная заявка на доступ к API Директа для пользовательского OAuth-приложения; выделенный тестовый аккаунт Директа (сейчас `artembakradze`, в котором могут быть настоящие кампании).
- **Зависимость от других изменений**: дельты относятся к требованиям из `bootstrap-ad-autopilot-mvp`, которое ещё не архивировано. Это изменение архивируется после него.
- **Не меняется**: ядро, ограничители, `budget-guard`, страховочные правила, агент, история изменений — они работают с контрактом площадки и не зависят от режима.
