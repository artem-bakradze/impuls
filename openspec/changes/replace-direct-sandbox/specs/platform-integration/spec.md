## ADDED Requirements

### Requirement: Режимы симулятора и боевого API
The system SHALL поддерживать два режима окружения: симулятор рекламного рынка и боевой API Директа. Режим задаётся конфигурацией окружения, а не пользователем. Локальная разработка, CI и staging SHALL работать в режиме симулятора. Конфигурация с неизвестным режимом, в том числе с прежним значением режима песочницы, MUST отклоняться при старте с явной ошибкой. В режиме симулятора интерфейс MUST постоянно показывать плашку «Тестовый режим — реклама не показывается».

#### Scenario: Окружение разработки
- **WHEN** сервис запущен в режиме симулятора
- **THEN** ни один вызов не уходит в API Директа, кампании создаются в симуляторе, а на каждой странице видна плашка тестового режима

#### Scenario: Устаревшая конфигурация песочницы
- **WHEN** сервис запускается с режимом песочницы, оставшимся от прежней конфигурации
- **THEN** worker и web не стартуют и сообщают, что режим песочницы больше не поддерживается и допустимы только режимы симулятора и боевого API

#### Scenario: Боевой режим
- **WHEN** сервис запущен в режиме боевого API
- **THEN** все вызовы идут в боевой API Директа от имени подключённого аккаунта пользователя, а плашка тестового режима не показывается

## MODIFIED Requirements

### Requirement: Подключение аккаунта Директа
The system SHALL подключать собственный аккаунт Яндекс Директа пользователя через Яндекс OAuth с доступом к API Директа и Метрики. Подключение SHALL идти через OAuth-приложение Яндекса для авторизации пользователей с адресом возврата в сервисе; приложение для ручной отладки MUST NOT использоваться для подключения пользователей. Запрос авторизации MUST содержать одноразовый параметр `state`, привязанный к сессии пользователя, и ответ с несовпадающим или повторно использованным `state` MUST отклоняться. Токены MUST храниться в зашифрованном виде и обновляться автоматически. Агентские аккаунты и аккаунты в валюте, отличной от рубля, в MVP SHALL отклоняться с понятным объяснением.

#### Scenario: У пользователя нет аккаунта Директа
- **WHEN** пользователь авторизовался в Яндексе, но аккаунта Директа у него нет
- **THEN** система показывает пошаговую инструкцию со ссылкой на создание аккаунта и проверяет его появление при нажатии «Я создал аккаунт»

#### Scenario: Токен отозван
- **WHEN** запрос к API возвращает ошибку авторизации
- **THEN** система приостанавливает автоматические действия по этому пользователю, показывает на сводке «Потерян доступ к Яндекс Директу — подключите заново» и отправляет уведомление на email; кампании продолжают работать с последними настройками и лимитами в Директе

#### Scenario: Пользователь отказался от доступа
- **WHEN** пользователь на странице Яндекса нажал «Отмена» вместо «Разрешить»
- **THEN** система возвращает его на шаг подключения с текстом «Без доступа к Яндекс Директу мы не сможем запустить рекламу» и кнопкой повторного подключения, а токен не сохраняется

#### Scenario: Подложный ответ авторизации
- **WHEN** на адрес возврата приходит ответ с параметром `state`, который не выдавался этой сессии или уже был использован
- **THEN** система не обменивает код на токен, ничего не сохраняет и показывает «Не удалось подключить Яндекс Директ — попробуйте ещё раз»

### Requirement: Структура создаваемых кампаний
The system SHALL создавать в Директе для каждого «направления» отдельную кампанию. Направление — это пара «группа услуг × канал»; каналы — «Поиск» и «Сайты-партнёры» (РСЯ). Кампания направления «Поиск» MUST показываться только в поиске, кампания направления «Сайты-партнёры» — только на сайтах-партнёрах. Каждой кампании SHALL назначаться:
- зона показа: регионы Директа, покрывающие зону показа бизнеса;
- расписание по часам работы бизнеса;
- цели Метрики;
- лимит расходов, выставленный `budget-guard`;
- мониторинг доступности сайта: площадка приостанавливает показы, если посадочная страница не открывается.

Внутри каждой кампании система SHALL создавать группу объявлений с зоной показа кампании. Для направления «Поиск» группа MUST содержать хотя бы одну ключевую фразу и минус-фразы из `ad-creatives`; без ключевых фраз поисковое направление MUST NOT создаваться. Каждое объявление MUST вести на собственный сайт бизнеса со ссылкой, размеченной UTM-метками сервиса, по которым обращения сопоставляются с направлением и объявлением.

Стратегия с оплатой за обращения SHALL назначаться только вместе с целью Метрики, по которой считаются обращения, и целевой стоимостью обращения, равной ЦСО из `optimization-engine`. Если у бизнеса нет цели Метрики, команда на эту стратегию MUST отклоняться с причиной «нет цели для подсчёта обращений», а кампания остаётся на прежней стратегии.

Сервис SHALL сам проверять доступность посадочных страниц не реже раза в 15 минут и предупреждать пользователя. Все кампании, созданные сервисом, MUST помечаться так, чтобы сервис отличал их от кампаний, созданных пользователем вручную. Кампании, созданные не сервисом, MUST оставаться нетронутыми.

#### Scenario: В аккаунте уже есть ручные кампании
- **WHEN** у пользователя в Директе есть кампании, созданные не сервисом
- **THEN** система их не изменяет, не останавливает и не учитывает в бюджете сервиса, а на шаге подключения предупреждает, что их расходы не входят в бюджет сервиса

#### Scenario: Посадочная страница не открывается
- **WHEN** сайт пользователя перестал открываться
- **THEN** показы кампаний с этой страницей приостанавливаются мониторингом Директа, а сервис показывает на сводке «Ваш сайт не открывается — показы приостановлены, чтобы не тратить деньги впустую» и отправляет email

#### Scenario: Запуск поискового направления
- **WHEN** пользователь запускает направление «Маникюр — Поиск» с 12 ключевыми фразами, 5 минус-фразами и двумя объявлениями
- **THEN** в Директе появляется кампания с показами только в поиске, одной группой с регионами зоны показа, 12 ключевыми и 5 минус-фразами и двумя объявлениями, ссылки которых ведут на сайт бизнеса с UTM-метками этого направления и объявления

#### Scenario: Запуск направления «Сайты-партнёры»
- **WHEN** пользователь запускает направление «Маникюр — Сайты-партнёры»
- **THEN** в Директе появляется кампания с выключенными показами в поиске и включёнными на сайтах-партнёрах, а ключевые фразы для её запуска не требуются

#### Scenario: Поисковое направление без ключевых фраз
- **WHEN** для направления «Поиск» не подобрано ни одной ключевой фразы
- **THEN** кампания не создаётся, а пользователь видит «Не получилось подобрать поисковые запросы для этой услуги — уточните описание услуги»

#### Scenario: Стратегия с оплатой за обращения без цели Метрики
- **WHEN** агент предлагает перевести направление на оплату за обращения, а у бизнеса нет цели Метрики
- **THEN** команда отклоняется с причиной «нет цели для подсчёта обращений», стратегия кампании в Директе не меняется, а в журнале хода записан отказ

#### Scenario: Город бизнеса
- **WHEN** пользователь запускает рекламу с городом «Казань»
- **THEN** все кампании сервиса и их группы создаются с регионом «Казань» из справочника регионов Директа

## REMOVED Requirements

### Requirement: Режимы песочницы и боевого API
**Reason**: Яндекс отключил песочницу API Директа 15.07.2026.
**Migration**: Требование заменено на «Режимы симулятора и боевого API»: разработка, CI и staging переходят на режим симулятора, совместимость с API Директа проверяется контрактными тестами `testing-harness` на боевом API.
