## Context

Разбор студии (`Review` в `SimulationStudio`) берёт последнюю запись журнала (`JournalEntry` из `buildServiceWork`): `headline`, `paragraphs` (разбор дня или недели словами агента, иначе наблюдения инсайтов), `changes` (изменения с откатом, фактами и ходом), `checking` (открытые проверки недели с днём), `found` (закрытые проверки). Поле инсайта «Что дальше» (`InsightCardModel.next`) в журнал не попадает. Агент пишет `next` по инструкции «что и к какому дню проверишь»; тестовые политики (`packages/agent/src/policies.ts`) и страховочные правила (`apps/worker/src/insights.ts`) — шаблонами «Через неделю проверим…». Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Разбор читается как текст: рассуждение → решение → ожидаемый эффект, словами сервиса.
- Ни одного нового числа сверх того, что сервис уже написал и проверил по фактам.
- Одна главная кнопка студии, всегда в одном месте — под объявлениями.

**Non-Goals:**
- Писать текст разбора отдельным вызовом модели: это новая трата и новый непроверенный текст. Записка собирается из того, что агент уже написал и что прошло проверку фактов.
- Менять историю, ленту инсайтов и главный экран: там остаются свои виды.
- Запускать платный eval агента: только по запросу.

## Decisions

**1. Записка из полей журнала.** `JournalEntry` получает `expects: string[]` — «Что дальше» инсайтов записи (агента или правил, с изменением или без), через `plain()` и с точкой, без повторов. `Review` строит три абзаца:
- «Что вижу» = `headline` и `paragraphs` + «Выяснил: {statement} — {outcome}. {result}» для закрытых проверок;
- «Что сделал» = каждое изменение предложением с точкой; у обратимого — текстовая кнопка «Вернуть как было», у отменённого — «— вы вернули как было» приглушённо;
- «Чего жду» = ожидания из `expects` и проверки из `checking`, сгруппированные по дню: «16 ноября проверю, продолжит ли … и останется ли …». Префикс «Проверяю, » снимается, как в строке «Дальше» на главной. Когда проверки есть, ожидание, которое только называет проверку («К 16 ноября проверю стоимость…»), отбрасывается: его нет смысла читать дважды. Признак ожидаемого эффекта — слова «жду», «ожида», «должн», «больше», «меньше», «дешевле», «вырас», «снизит», «перейдут»; без них при проверках строка считается повтором.
Функции сборки — чистые, в отдельном `review-note.ts` (`noteTitle`, `noteSeen`, `noteSentence`, `noteExpect`), с модельными тестами.

**2. Вид записки.** Метки абзацев — маленькие, цвета `--accent-ink`, на своей строке; текст — 15 px, межстрочный 1,6, цвет основного текста; «Что сделал» — полужирным, это главное. Заголовок — «Разбор недели · 9 ноября». Под текстом — одна ссылка «Подробнее — в истории ›» на `/summary#log-{id}`. Без рамок, плашек и списков: записка, а не форма.

**3. Кнопки шага под списком.** `stageActions` всегда истинно: блок кнопок под объявлениями (липкий на компьютере по `refresh-workspace-look`, над списком на телефоне). Состояние согласия (`acknowledged`) удаляется. На телефоне разбор по-прежнему стоит над сценой.

**4. «Что дальше» с ожидаемым эффектом.** Инструкции агента: «next — сначала чего ждёшь от решения (направление изменения без новых чисел и без обещаний), затем к какому дню проверишь: «Жду больше обращений с компьютеров по цене не выше цели — проверю к 16 ноября». Для наблюдения без действия — к какому дню вернёшься к вопросу». Описание поля `next` в инструменте — так же. Версии `AGENT_INSTRUCTIONS_VERSION` и `WEEKLY_REVIEW_INSTRUCTIONS_VERSION` — `2026-11-04.1`. Тексты тестовых политик и страховочных правил переписаны по тому же образцу («Деньги перейдут к объявлениям, которые приводят обращения, — через неделю сравню цену обращения этой рекламы с целью»); BDD «Инсайт об отключении» проверяет, что «Что дальше» начинается с ожидаемого эффекта. Как пишет ожидание модель, проверяет eval агента (по запросу). Проверка фактов инсайта не меняется: ожидание без чисел ей не мешает.

## Risks / Trade-offs

- [Старые записи на стенде пишут «Что дальше» без эффекта] → Для записей с проверками «Чего жду» строится из проверок с днями; для остальных показывается то, что сервис написал. Новые ходы пишут по-новому.
- [Эвристика «ожидание или только проверка» ошибается] → Ошибка видна только как лишнее или пропущенное предложение в «Чего жду»; проверки с днями показываются всегда. Модельные тесты закрепляют оба случая.
- [Без «Почему так» владелец не видит факты в студии] → Числа решения уже в «Что вижу» словами сервиса, а полный список фактов и ход агента — в истории по ссылке «Подробнее — в истории».
- [Инструкции изменены без eval] → Изменение касается только формулировки одного поля; eval запускается по запросу заказчика.
