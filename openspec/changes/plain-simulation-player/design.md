## Context

Окно статистики строится по `PeriodForm` (`apps/worker/src/simulation-period.ts`): объявления, которые показываются, и предел расхода направления на 1, 3, 7 и 14 дней. Внесённые цифры каждого периода хранятся в шаге записи симуляции (`steps[].input`). Проверки окна — чистая `checkPeriod`.

## Goals / Non-Goals

**Goals:** правдоподобные цифры одним нажатием, которые продолжают прошлый период объявления и всегда проходят проверки.

**Non-Goals:** модель рынка, прогноз, случайность от нажатия к нажатию; менять API и запись симуляции.

## Decisions

**1. Прошлый период — из сохранённых шагов.** `savedPeriodForm` проходит завершённые шаги-периоды и для каждого объявления запоминает последнюю ненулевую строку его цифр с длиной периода. Строка попадает в форму как `ads[].last`. Альтернатива — читать статистику по дням — отклонена: внесённые числа и так лежат в шаге, а в статистике они уже разложены по дням.

**2. `suggestPeriod(form, days)` — чистая и детерминированная.** Разброс задаёт хэш от id объявления, первого дня и длины периода, поэтому то же окно даёт те же цифры, а у разных объявлений они разные. Для каждого направления:
- бюджет — 70% предела за период;
- бюджет делится между объявлениями пропорционально расходу в день прошлого периода (без него — поровну) с разбросом ±20%;
- цена перехода, доля переходов и доля обращений берутся из прошлого периода объявления, с разбросом ±15% у доли обращений;
- без прошлого периода: поиск — переход 30–60 ₽ и 4–8% переходов от показов, сайты-партнёры — 12–24 ₽ и 0,5–1%; доля обращений 2–12% по хэшу id, то есть постоянная для объявления;
- переходы — доля бюджета, делённая на цену перехода, с округлением; расход — вся доля, поэтому цена перехода остаётся близкой к прежней; показов не меньше, чем переходов, обращений не больше, чем переходов.

Так расход направления не выходит за его долю бюджета, а значит и за предел. Объявление без обращений в прошлом периоде остаётся без них: сервису есть что разбирать дальше.

**3. Интерфейс.** Кнопка «Заполнить примерно» стоит под переключателем периода и заполняет поля для выбранного периода; смена периода не трогает уже вписанное. В плеере пропадает метка статуса, а «Запустить по-настоящему» становится вторым пунктом меню. В шапке ответа в симуляции нет подписи периода; `adsStateText` для идущей рекламы — «реклама активна».

## Risks / Trade-offs

- [Детерминированные цифры одинаковы при повторном открытии окна] → это и нужно для проверки; владелец правит любые поля.
- [«реклама активна» меняет и режим Директа] → число объявлений стоит в строке «Объявления N» рядом, повтор не нужен.
