## MODIFIED Requirements

### Requirement: Ходы агента
The system SHALL поддерживать агента на OpenAI Agents API как необязательное дополнение к детерминированным правилам. По умолчанию агент MUST быть выключен глобальным выключателем. Включает его команда сервиса глобально, без перезапуска. Выключить агента можно глобально или для отдельного бизнеса. Запуск рекламы, отключение неэффективного, масштабирование эффективного и эксперименты MUST работать при выключенном агенте (`optimization-engine`, `ab-testing`).

Когда агент включён, система SHALL запускать его ходами (turn). Ход SHALL запускаться событиями:
- запуск рекламы из мастера — разбор созданной структуры кампаний;
- ежедневный разбор после обновления статистики (после 06:00 по времени бизнеса);
- отклонение объявления модерацией;
- завершение эксперимента;
- изменение пользователем настроек, бюджета или цели.

Каждый ход MUST выполняться в отдельной сессии OpenAI Agents API. После сохранения журнала хода сессия SHALL удаляться. Всё, что агенту нужно знать о прошлом, он получает из снимка хода и инструментов чтения сервиса, а не из накопленного контекста сессии. Ходы MUST быть изолированы между бизнесами: агент одного бизнеса не видит данных другого.

#### Scenario: Агент выключен по умолчанию
- **WHEN** сервис развёрнут с нуля, и пользователь запускает рекламу
- **THEN** кампании создаются, ходы агента не запускаются, а ежедневная оценка и страховочные правила работают

#### Scenario: Ежедневный разбор
- **WHEN** агент включён, и в 06:00 по времени бизнеса обновлена статистика за прошедший день
- **THEN** система создаёт сессию, передаёт в неё триггер и снимок, агент выполняет ход с вызовами инструментов, а после сохранения журнала сессия удаляется

#### Scenario: Новая версия инструкций
- **WHEN** разработчики выпустили новую версию инструкций агента
- **THEN** все ходы, начатые после выпуска, используют новую версию, а в журнале каждого хода записано, с какой версией он выполнялся

### Requirement: Доступ только через инструменты сервиса
The system SHALL предоставлять агенту только function tools, которые выполняет сам сервис. Агент MUST NOT получать OAuth-токены, прямой доступ к API Директа или к базе данных. Бизнес и рекламный аккаунт для каждого вызова MUST определяться сервером по привязке хода, а не по аргументам инструмента. Объект другого бизнеса в аргументах MUST приводить к отказу без раскрытия его данных.

Инструменты чтения:
- карточка бизнеса, цель и бюджет с остатком на месяц;
- текущая структура кампаний, стратегии, лимиты и доступный каталог стратегий площадки;
- снимок статистики за 14 и 30 дней с классификацией эффективности из `optimization-engine`;
- активный эксперимент;
- история изменений и откатов пользователя.

Инструменты действий:
- создать или изменить направление (кампанию), стратегию, лимит расходов, расписание;
- поставить на паузу или возобновить объявление или направление;
- добавить или изменить объявление, ключевые и минус-фразы;
- запустить эксперимент;
- запросить варианты объявлений у `ad-creatives`.

#### Scenario: Агент пытается обратиться к площадке напрямую
- **WHEN** агент в ответе описывает действие, для которого нет инструмента
- **THEN** действие не выполняется, а система записывает такой ход в журнал агента как ход без действий

#### Scenario: Объект другого бизнеса
- **WHEN** агент передаёт в инструмент ID кампании, которая принадлежит другому бизнесу
- **THEN** вызов отклоняется с причиной «объект не найден», и никакие данные другого бизнеса агенту не возвращаются

### Requirement: Работа без агента
The system SHALL работать полноценно, если агент выключен (по умолчанию), Agents API недоступен или ход завершился ошибкой. Выключатель агента SHALL действовать глобально или для отдельного бизнеса, срабатывать в течение минуты и не требовать перезапуска или обновления сервиса. Без агента:
- запуск из мастера создаёт кампании по структуре «услуги × канал» (`platform-integration`);
- `budget-guard`, классификация и страховочные правила `optimization-engine` отключают неэффективное и масштабируют эффективное;
- эксперименты для пограничной рекламы запускает страховочное правило `ab-testing` с вариантом из `ad-creatives`;
- стратегии кампаний не меняются.

Если агент включён, но недоступен дольше 24 часов, команда сервиса SHALL получать инцидент.

#### Scenario: Agents API недоступен двое суток
- **WHEN** агент включён, а все запросы к Agents API возвращают ошибки 48 часов
- **THEN** бюджет не превышен, явно неэффективные объявления отключены страховочными правилами, а команда получила инцидент

#### Scenario: Агент выключен для одного бизнеса
- **WHEN** команда сервиса выключает агента для бизнеса
- **THEN** в течение минуты новые ходы для этого бизнеса не запускаются, текущий ход прерывается, а страховочные правила и `budget-guard` продолжают работать

#### Scenario: Месяц без агента
- **WHEN** агент выключен, а у бизнеса одно неэффективное объявление, одно эффективное направление, упирающееся в лимит, и одно пограничное объявление
- **THEN** неэффективное объявление поставлено на паузу, лимит эффективного направления увеличен, для пограничного объявления запущен эксперимент, каждое действие есть в истории с объяснением, а отключение и изменение лимита можно откатить

## REMOVED Requirements

### Requirement: Память агента между ходами
**Reason**: Агент выключен по умолчанию. Заметки не видны пользователю, а нужные агенту факты (проверенные гипотезы, откаты) есть в истории изменений и экспериментах, которые он читает инструментами.
**Migration**: Инструменты заметок удаляются из агента, таблица заметок — из базы. Проверенные гипотезы агент получает из истории экспериментов.

### Requirement: Режим «Спрашивать перед крупными изменениями»
**Reason**: Режим удалён вместе с требованием «Уровень самостоятельности» (`campaign-settings`).
**Migration**: Действия агента всегда выполняются через исполнитель команд без подтверждения. Несогласие пользователь выражает откатом.
