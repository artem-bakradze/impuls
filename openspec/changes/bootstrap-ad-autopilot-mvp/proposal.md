## Why

Владелец маленького бизнеса (маникюрный салон, йога-студия, барбершоп) не может и не хочет разбираться в рекламных кабинетах, ставках и ключевых фразах. Встроенные «простые режимы» площадок (Яндекс Бизнес, быстрый запуск VK Рекламы) запускают рекламу, но не показывают честную стоимость клиента, не объясняют свои решения и не гарантируют, что бюджет не будет превышен. Сервис «Импульс» закрывает именно этот разрыв: человек описывает бизнес и задаёт бюджет, а сервис сам запускает и оптимизирует рекламу, объясняя каждое действие простым языком и позволяя его откатить.

Исходное ТЗ заказчика оставляло неопределёнными сроки, допуски и модель работы с кабинетами. Этот документ фиксирует их как проверяемые требования.

## What Changes

- Новый веб-сервис с входом через Google и мастером запуска: описание бизнеса → «как мы вас поняли» → что считать клиентом → бюджет → превью объявлений → подключение Яндекс Директа → запуск.
- Интеграция с **Яндекс Директом** (API v5) как с первой и в MVP единственной площадкой. Разработка и автотесты идут против **песочницы Директа**, пилот — против боевого API. Слой площадок проектируется через адаптер, чтобы второй площадкой подключить VK Рекламу без переделки ядра.
- ИИ-агент на **OpenAI Agents API** строит структуру кампаний и стратегии в Директе и ежедневно их оптимизирует: отключает неэффективное, перераспределяет бюджет в пользу эффективного, предлагает гипотезы для A/B-тестов. Агент работает только через инструменты сервиса. Каждое его действие проходит детерминированные ограничители: бюджет, размер шага, частота изменений, уважение к откатам. Страховочные правила в коде гарантируют отключение явно неэффективного и масштабирование явно эффективного, даже если агент ошибся или недоступен.
- Контур защиты бюджета: жёсткие лимиты на стороне площадки с запасом, страховочная остановка со стороны сервиса и ежечасная сверка с кабинетом Директа — лимиты, поднятые вручную, урезаются до допустимых. В первый неполный месяц бюджет считается пропорционально оставшимся дням.
- Аналитика: расходы, обращения, клиенты, стоимость клиента. Данные берутся из Reports API Директа и Яндекс Метрики; количество клиентов пользователь подтверждает сам.
- История изменений: что изменено, почему, что стало после; откат с предупреждением о последствиях.
- Мини-сайт для бизнеса без сайта: у многих салонов есть только карточка на Картах или группа ВК, а без посадочной страницы со счётчиком невозможно посчитать обращения. Мини-сайты публикуются статикой на отдельном домене и не зависят от работы приложения.
- Генерация текстов объявлений на основе описания бизнеса с учётом требований модерации и закона о рекламе.
- Тестовый контур: симулятор рекламного рынка; проверка ограничителей и бюджета с тестовыми политиками вместо агента, включая «агента-вредителя»; eval-набор для настоящего агента; e2e-прогон интерфейса пользователями-персонами на OpenAI Agents API + Playwright.

### Отклонения от исходного ТЗ заказчика (требуют согласования)

- **Одна площадка вместо двух.** Исходное ТЗ требует минимум две площадки через прямые API. MVP сознательно ограничен Яндекс Директом; VK Реклама — следующий этап, под который заложен адаптер.
- **Песочница не подтверждает критерии 3, 4, 6.** В песочнице объявления не показываются, а статистика условная. Подтверждать реальное отключение неэффективной рекламы, A/B-тест и совпадение статистики с кабинетом нужно на пилоте с реальным бюджетом.
- **Изображения и видео в креативах** (дополнительное преимущество в исходном ТЗ) не входят в MVP.

### Non-goals

- Оплата, тарифы, роли и управление доступами.
- Пополнение рекламных кабинетов (делается вне сервиса).
- Автоматизация действий в веб-интерфейсе кабинета через браузер (Playwright MCP) в продакшене. Допускается только если найдётся действие, недоступное через API, и отдельным изменением.
- Агентская модель (кабинеты под аккаунтом сервиса). В MVP каждый пользователь подключает собственный аккаунт Директа через OAuth.

## Capabilities

### New Capabilities

- `auth`: вход и регистрация через Google, сессии.
- `business-onboarding`: мастер запуска — сбор и разбор описания бизнеса, цели «что считать клиентом», выбор бюджета, превью, запуск.
- `platform-integration`: подключение Яндекс Директа через OAuth, адаптер площадки, создание и изменение кампаний, режимы песочница/боевой.
- `ad-creatives`: генерация и проверка текстов объявлений, обработка отказов модерации.
- `budget-guard`: гарантия непревышения месячного бюджета.
- `ad-agent`: агент на OpenAI Agents API — ходы и память агента, инструменты, обоснование действий, минимизация данных, лимиты, работа без агента, журнал.
- `optimization-engine`: целевая стоимость обращения, классификация эффективности, ограничители действий агента и страховочные правила.
- `ab-testing`: эксперименты для объявлений с пограничной эффективностью, вывод и применение решения.
- `mini-site`: одностраничный сайт для бизнеса без собственного сайта, со встроенным счётчиком Метрики и целями.
- `analytics`: сбор статистики из Директа и Метрики, установка счётчика, подтверждение клиентов, сводка и сверка с кабинетом.
- `change-history`: журнал изменений с объяснениями и откатом.
- `campaign-settings`: просмотр и изменение настроек простым языком, уровень самостоятельности сервиса, уведомления.
- `testing-harness`: симулятор рынка, сценарии ограничителей с тестовыми политиками, eval агента, e2e-тесты с симулированными пользователями.

### Modified Capabilities

Нет: проект создаётся с нуля.

## Impact

- **Новая кодовая база**: веб-приложение, фоновые воркеры, PostgreSQL.
- **Внешние API**: Яндекс Директ API v5 (боевой и песочница), Яндекс Метрика (Management и Reporting API), Яндекс OAuth, Google OAuth, OpenAI Agents API (публичная бета: агент оптимизации и агенты-персоны в тестах), OpenAI API (извлечение карточки бизнеса, генерация текстов).
- **Персональные данные**: сервис обрабатывает персональные данные граждан РФ, поэтому по 152-ФЗ база данных размещается на серверах в России. Agents API хранит данные в США и не поддерживает Zero Data Retention, поэтому в агента передаются только публичные данные о бизнесе и агрегированная статистика.
- **Доступность OpenAI**: API OpenAI недоступен из России. Технически обращения идут через HTTPS-прокси за пределами РФ, который не видит ни данных, ни ключей. Но условия OpenAI допускают блокировку аккаунта при доступе или предоставлении доступа вне поддерживаемых стран, поэтому нужна юридическая проверка. Агент и LLM-задачи стоят за заменяемыми портами, а сервис безопасно работает без агента.
- **Организационные зависимости**: заявка на доступ к API Директа (проходит модерацию у Яндекса, срок от команды не зависит), регистрация OAuth-приложений Google и Яндекса, маркировка рекламы через встроенный Яндекс ОРД в аккаунте рекламодателя.
- **Пилот**: нужен минимум один реальный бизнес с бюджетом и 3–4 неделями открутки, чтобы подтвердить критерии приёмки, которые в песочнице не проверяются.
